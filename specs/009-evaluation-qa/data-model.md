# Data Model: Post-Evaluation Q&A with Audio Responses

**Feature**: 009-evaluation-qa  
**Date**: 2025-11-10  
**Status**: Complete

## Overview

This document defines the data entities, relationships, and state transitions for the Q&A feature. All data is managed client-side using IndexedDB with n8n API integration for question generation and answer rating.

## Entity Definitions

### QASession

Represents a post-evaluation question and answer session.

**Fields**:

- `id`: string (UUID) - Unique identifier for the session
- `evaluationId`: string (UUID) - Links to completed evaluation (from evaluation API)
- `questions`: Question[] - Array of LLM-generated questions (3-5 items)
- `answers`: Map<string, AudioAnswer> - Map of questionId to audio answer
- `currentQuestionIndex`: number - Current question being viewed/answered (0-based)
- `status`: SessionStatus - Current session state
- `createdAt`: Date - Session creation timestamp
- `updatedAt`: Date - Last modification timestamp

**Relationships**:

- One-to-one with Evaluation (via evaluationId)
- One-to-many with Question (questions array)
- One-to-many with AudioAnswer (answers map)

**State Transitions**:

```
'not-started' → 'active' → 'completed'
     ↓             ↓
   (initial)   (paused/resumed)
```

**Validation Rules**:

- questions.length must be 3-5
- evaluationId must reference valid evaluation
- currentQuestionIndex must be within questions array bounds
- status cannot transition backwards (completed → active is invalid)

**Storage**: IndexedDB (`qaSessionsStore`)

---

### Question

Represents an LLM-generated question based on evaluation performance.

**Fields**:

- `id`: string (UUID) - Unique question identifier
- `text`: string - Question content (max 500 characters)
- `order`: number - Display order (1-5)
- `context`: string? - Optional context or hint for the question
- `evaluationId`: string - Links to source evaluation
- `createdAt`: Date - Question generation timestamp

**Relationships**:

- Many-to-one with QASession
- One-to-one with AudioAnswer (optional, if answered)

**Validation Rules**:

- text must not be empty
- order must be unique within a session
- order must be 1-5 (matching question count range)

**Source**: Generated by n8n `/comm-ai/generate-questions` API

---

### AudioAnswer

Represents a user's recorded audio response to a question.

**Fields**:

- `id`: string (UUID) - Unique answer identifier
- `questionId`: string (UUID) - Links to question being answered
- `audioBlob`: Blob - Recorded audio data
- `audioFormat`: AudioFormat - Format of audio (webm or mp4)
- `duration`: number - Recording duration in seconds
- `uploadStatus`: UploadStatus - Current upload state
- `answerId`: string? - Server-assigned answer ID (after successful upload)
- `rating`: AnswerRating? - Rating received from server (null until rated)
- `submittedAt`: Date - Answer submission timestamp
- `ratedAt`: Date? - Rating received timestamp

**Relationships**:

- Many-to-one with Question (via questionId)
- One-to-one with AnswerRating (optional, embedded)

**Validation Rules**:

- audioBlob size < 50MB (safety limit)
- duration > 0 (must have content)
- audioFormat must be 'webm' or 'mp4'
- uploadStatus must follow valid transition path
- rating only present when uploadStatus is 'uploaded'

**State Transitions**:

```
'pending' → 'uploading' → 'uploaded'
               ↓
            'error' → 'pending' (retry)
```

**Storage**:

- Temporary: IndexedDB blob until uploaded
- Permanent: Server storage (managed by n8n)
- Retention: 7 days in IndexedDB (cleanup policy)

---

### AnswerRating

Represents the evaluation/rating of an audio answer (embedded in AudioAnswer).

**Fields**:

- `score`: number - Numeric score (0-100)
- `feedback`: string - Text feedback (max 300 characters)
- `criteria`: RatingCriteria? - Optional detailed scoring breakdown
- `ratedAt`: Date - Rating generation timestamp

**Validation Rules**:

- score must be 0-100 (inclusive)
- feedback must not be empty
- feedback max length 300 characters

**Source**: Generated by n8n `/comm-ai/rate-answer` API

---

### RatingCriteria (Optional Detail)

Optional detailed scoring breakdown (for future enhancement).

**Fields**:

- `clarity`: number (0-100) - Speech clarity score
- `accuracy`: number (0-100) - Content accuracy score
- `completeness`: number (0-100) - Answer completeness score

---

## Enumerations

### SessionStatus

```typescript
type SessionStatus =
  | "not-started" // Created but no questions loaded
  | "active" // Questions loaded, user answering
  | "completed"; // All questions answered and rated
```

### UploadStatus

```typescript
type UploadStatus =
  | "pending" // Recorded but not uploaded
  | "uploading" // Upload in progress
  | "uploaded" // Successfully uploaded and acknowledged
  | "error"; // Upload failed (can retry)
```

### AudioFormat

```typescript
type AudioFormat =
  | "webm" // WebM audio (Opus codec) - Chrome, Firefox
  | "mp4"; // MP4 audio (AAC codec) - Safari, Edge
```

## Data Flow

### Question Generation Flow

```
1. User completes evaluation → evaluationId available
2. User clicks "Start Q&A" → QASession created (status: 'not-started')
3. Call GET /comm-ai/generate-questions?evaluationId={id}
4. Questions returned → Store in qaSessions.questions
5. Session status → 'active'
6. Render first question in chat UI
```

### Answer Submission Flow

```
1. User records audio → AudioAnswer created (uploadStatus: 'pending')
2. User submits → uploadStatus: 'uploading'
3. Upload audio to n8n (POST /comm-ai/rate-answer with multipart/form-data)
4. If success → uploadStatus: 'uploaded', response includes server answer id plus rating payload (id, createdAt, score, feedback)
5. Persist answerId and derive ratedAt from the returned createdAt
6. Rating stored on AudioAnswer.rating → Update UI immediately
7. User can proceed to next question (non-blocking)
```

### Session Persistence Flow

```
1. On any state change → Update IndexedDB immediately
2. On page load → Load QASession from IndexedDB by evaluationId
3. Restore questions, answers, current index
4. Resume from last position
5. Cleanup: Delete sessions older than 7 days (on app init)
```

## Data Validation

### Client-Side Validation

- Audio format must be webm or mp4 (validate before upload)
- Audio duration > 0 (reject empty recordings)
- Audio file size < 50MB (validate before upload)
- Question text not empty (validate on API response)
- Score 0-100 (validate on rating response)

### Server-Side Validation (n8n)

- evaluationId exists (question generation)
- audioFile is valid audio format (answer rating)
- Audio file size < 50MB
- Valid audio format (can be processed)

## Error Handling

### Question Generation Errors

- LLM service failure → Fallback to generic questions
- Network error → Retry with exponential backoff (3 attempts)
- Invalid evaluationId → Show error, redirect to evaluations page

### Answer Upload Errors

- Network timeout → Set uploadStatus: 'error', offer retry
- Server error (500) → Set uploadStatus: 'error', show error message
- Audio format unsupported → Show format error, suggest re-recording
- File too large → Show size error, suggest shorter recording

### Rating Response Errors

- HTTP timeout (>30s) → Keep answer in `uploading` state until fetch resolves or fails, then show "Rating taking longer than expected. Please retry."
- Server error → Show error message, offer manual retry
- Missing rating payload → Treat as failure, log it, and prompt user to retry submission

## Performance Considerations

- Index questions by order for O(1) lookup
- Index answers by questionId for O(1) retrieval
- Lazy load audio blobs (only load when playing)
- Cleanup: Auto-delete uploaded audio blobs from IndexedDB after 24 hours
- Limit stored sessions to 10 most recent (LRU eviction)

## Privacy & Security

- Audio blobs stored only temporarily in IndexedDB
- Clear audio data after successful upload (optional, configurable)
- No PII in question/answer metadata
- All n8n API calls over HTTPS
- Microphone permissions requested with clear explanation
